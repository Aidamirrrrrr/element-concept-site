# ELEMENT CONCEPT — сайт студии флористики и сет-дизайна

**Демо: https://aidamirrrrrr.github.io/element-concept-site/**

Статический сайт на HTML/CSS/JS, раздаётся сервером на Bun. Он же принимает заявки
и заказы и складывает их в текстовые файлы.

На GitHub Pages выложена только статика: бэкенда там нет, поэтому формы работают
в демонстрационном режиме и честно сообщают, что заявка никуда не уходит.
Публикация автоматическая — `.github/workflows/pages.yml` заливает папку `site/`
при каждом пуше в `main`.

## Запуск

```bash
bun run start
```

Откроется на http://localhost:3000. Для разработки — `bun run dev` (автоперезапуск).

## Структура

```

├── css/fonts.css     локальные шрифты (генерируется)
├── js/data.js        контент: товары, кейсы, услуги (генерируется)
```

## Сборка ассетов

```bash
bun run build           # шрифты + картинки + data.js
bun run build:fonts     # скачать с Google Fonts, подрезать глифы, собрать fonts.css
bun run build:assets    # webp в 480/960/1440 + jpg-запаска, сгенерировать data.js
```

Контент берётся из `source/data/*.json`, картинки — из `source/media/`.
Данные товаров выгружены из store API Тильды: у каждой вазы своя галерея
(от 1 до 4 фото), артикулы в Тильде не заполнены — на сайте поле не выводим.

## Приём заявок

| Метод | Адрес | Тело | Куда пишет |
|---|---|---|---|
| POST | `/api/lead` | `{name, phone}` | `data/leads.txt` |
| POST | `/api/order` | `{name, email, city, items[]}` | `data/orders.txt` |

Оплаты нет: корзина оформляется как заявка — менеджер связывается и согласует детали.
Форма корзины показывается вторым шагом, после кнопки «Оформить заказ».

### Уведомления в Telegram

Заявка и заказ уходят боту сообщением, которое начинается с `САЙТ · НОВАЯ ЗАЯВКА`
или `САЙТ · НОВЫЙ ЗАКАЗ`. Настраивается двумя переменными в `.env`
(шаблон — в `.env.example`):

```
TELEGRAM_BOT_TOKEN=…
TELEGRAM_CHAT_ID=…
```

Без них сайт работает как обычно — заявки просто пишутся в файлы. Токен нигде
в коде не хранится и в репозиторий не попадает.

Сервер приводит телефон к `+7 (900) 000-00-00` (понимает ввод с `8` и без кода),
чистит управляющие символы, отбивает больше 5 отправок с адреса за 10 минут.

Пример записи:

```
──────────────────────────────────────────
ЗАКАЗ  07.08.2026, 13:03
Имя:      Ирина
Телефон:  +7 (903) 123-45-67
Состав:
  · Linen Trace — 1 шт. × 28 000 ₽ = 28 000 ₽
  · Sand Form — 2 шт. × 28 000 ₽ = 56 000 ₽
Итого:    84 000 ₽
Оплата:   не проводилась — связаться и согласовать
```

## Что умеет фронтенд

| Раздел | Поведение |
|---|---|
| Вазы | строка каталога открывает карточку — галерея с миниатюрами, описание, цена, «В корзину». Кнопка добавления есть и прямо в строке |
| Корзина | боковая панель, счётчик в шапке, +/−, удаление, итог, оформление заявки (Имя + Email — как в тильдовской корзине), сохраняется в `localStorage` |
| Кейсы | окно с полным текстом и галереей — 8–11 фото на кейс |
| Услуги | «Смотреть работы» открывает галерею услуги — 6–17 фото |
| Формы | маска `+7 (000) 000-00-00`, проверка полей, честное сообщение об ошибке сети |
| Навигация | подсветка активной секции, мобильное меню, `inert` на закрытых оверлеях |

## Анимация

Прелоадер со счётчиком · построчная и пословная развёртка заголовков ·
раскрытие фотографий маской `clip-path` · внутренний параллакс фото ·
параллакс блоков и крупных номеров · счётчики фактов · бегущая строка,
реагирующая на скорость прокрутки · магнитные кнопки · полоса прогресса чтения.

Всё на `transform` и `opacity`, один общий `requestAnimationFrame`.
Прокрутка нативная — так работают якоря, тачпад и колесо мыши ровно так,
как ожидает система. Курсор системный.

- `prefers-reduced-motion: reduce` — анимации и плавная прокрутка выключаются.
- До 900 px прелоадера нет и первый экран показывается сразу: анимация входа
  откладывала бы отрисовку заголовка.

## Lighthouse

На своём сервере (`bun run start`):

| | Performance | Accessibility | Best Practices | SEO |
|---|---|---|---|---|
| **Десктоп** | **100** | **100** | **100** | **100** |
| **Мобильный** | **97** | **100** | **100** | **100** |

На GitHub Pages (без инлайна CSS — там нет нашего сервера):

| | Performance | Accessibility | Best Practices | SEO |
|---|---|---|---|---|
| **Десктоп** | **99** | **100** | **100** | **100** |
| **Мобильный** | **96** | **100** | **100** | **100** |

Что для этого сделано:

- **WebP + srcset** в трёх размерах, `<picture>` с jpg-запаской, `width`/`height`
  у каждой картинки (CLS = 0), ленивая загрузка ниже первого экрана.
- **Локальные шрифты**, подрезанные до используемых символов (237 → 169 КБ).
- **Brotli/gzip** на лету с кэшем: HTML 60 → 13 КБ, CSS 29 → 6.5 КБ.
- **Весь CSS встроен в разметку** — ни одного блокирующего запроса. В `index.html`
  остаются обычные `<link>` в маркерах `<!--CSS-->`, сервер подменяет их на `<style>`;
  файл открывается и просто с диска.
- **CSP без `unsafe-inline`:** встроенный `<style>` разрешён по SHA-256 своего
  содержимого, инлайновые `style=""` в разметке запрещены совсем (`style-src-attr 'none'`)
  — задержки каскада вынесены в атрибут `data-i`. Плюс `object-src`, `frame-src`,
  `base-uri` в `'none'` и `upgrade-insecure-requests`.
- Разметка Schema.org одним `@graph`: `LocalBusiness`/`Florist`, `WebSite`, `WebPage`
  и `ItemList` из шести `Product` с ценами. Плюс Open Graph, canonical, sitemap,
  robots, манифест.
- Контраст текста проверен по WCAG AA (приглушённый цвет `#67695F` — 4.72:1 на фоне).

Мобильные 97 упираются в вес Literata: переменная антиква с кириллицей — 55 КБ,
и это главный элемент первого экрана. Оставшиеся 3 балла стоят замены заголовочного
шрифта, поэтому оставил как есть — это решение про дизайн, а не про код.

## Соответствие требованиям РФ

Это технический разбор, а не юридическое заключение: тексты документов
и реквизиты обязательно проверьте с юристом.

### Что сделано на сайте

| Требование | Как закрыто |
|---|---|
| Согласие на обработку ПДн (152-ФЗ, ст. 6 ч. 1 п. 1) | Обязательная отметка в обеих формах со ссылкой на политику. Без неё сервер заявку не примет |
| Фиксация согласия | В `data/leads.txt` и `data/orders.txt` пишется строка «Согласие: получено» с датой и временем |
| Публикация политики (152-ФЗ, ст. 18.1 ч. 2) | `site/policy.html`, ссылка в подвале на каждой странице |
| Сведения о продавце (ЗоЗПП, Правила продажи № 2463) | Блок реквизитов в подвале и раздел «Продавец» в `site/terms.html` |
| Условия доставки, оплаты, возврата (ЗоЗПП, ст. 26.1) | `site/terms.html`, включая семидневный срок отказа при дистанционной продаже |
| Маркировка Instagram | Сноска про Meta стоит рядом со ссылкой |
| Cookie-баннер | Не нужен: аналитики и рекламных cookie нет, `localStorage` хранит только состав корзины |

Готовый бриф для юриста — [docs/brief-lawyer.md](docs/brief-lawyer.md):
что за сайт, какие данные собирает, какие документы нужны и какие вопросы
требуют юридической позиции.

### Что нужно сделать вам

1. **Заполнить шаблоны.** В `policy.html` и `terms.html` места для ваших данных
   помечены красным и подписаны «заполнить»: организационная форма, ИНН, ОГРН(ИП),
   адрес, почта, сроки хранения, условия доставки и оплаты. То же — блок реквизитов
   в подвале `index.html`.
2. **Подать уведомление в Роскомнадзор** об обработке персональных данных.
   Это делается до начала сбора данных через формы.
3. **Разместить сервер в России.** Часть 5 статьи 18 152-ФЗ требует, чтобы данные
   россиян сначала записывались в базу на территории РФ. Сейчас демо стоит на
   GitHub Pages — это иностранный хостинг, и для боевого запуска он не годится.
4. **Учесть Telegram.** Уведомления уходят на серверы за пределами РФ. Первичная
   запись у нас идёт в файл на своём сервере, а бот — дублирующий канал, но это
   решение стоит согласовать с юристом.
5. **Проверить формулировки** политики и условий у юриста перед публикацией.
